# STM32F4 CAN 适配层

该模块管理经典 CAN 端点、硬件过滤器、收发缓冲和回调分发。所有对象使用固定
容量静态存储，初始化和运行阶段均不分配堆内存。

> 一条 CAN 总线必须恰好保留两个 120 Ω 终端。开发板、电调和电机可能自带可
> 配置终端，上板前需要实际测量并确认。

## 资源约束

- 最多注册 `CAN_MAX_INSTANCES`（当前 16）个端点。
- 每个 CAN 控制器最多使用 14 个过滤器组。
- 仅接受 11 位标准数据帧，载荷最大 8 字节。
- 同一 CAN 控制器上的接收 ID 必须唯一。
- 注册仅允许发生在单线程启动阶段。

`CANRegister()` 会验证句柄、标准 ID、容量和重复 ID，并配置一个 16 位 ID-list
过滤器。任何步骤失败都返回 `NULL`，调用方必须把它视为设备初始化失败。

## 回调上下文

系统提供两种全局分发模式：

- `CAN_DISPATCH_INTERRUPT`：默认兼容模式，在 CAN 中断中直接调用设备回调；
- `CAN_DISPATCH_DEFERRED`：中断只复制数据，任务调用
  `CANDispatchPending()` 后才执行设备回调。

必须在第一个端点注册前调用 `CANConfigureDispatch()`，注册后禁止改变模式。
正式机器人固件使用延迟分发；现有独立 demo 默认保持中断模式。

延迟模式为每个端点保留一个“最新值”收件箱。新反馈覆盖尚未消费的旧反馈，
因此每次任务分发最多解析每个端点的一帧最新状态。这适合电机、超级电容等
状态型协议，避免把 1 kHz 中断流量原样堆积到控制任务。覆盖次数记录在
`CANDispatchStats.coalesced_frames`，属于可观测的合并量，不等同于硬件丢包。

## 发送

调用方先写入端点的 `tx_buff`，必要时通过 `CANSetDLC()` 设置 1–8 字节载荷，
再调用：

```c
if (!CANTransmit(endpoint, 1000U)) {
    /* 1 ms 内无邮箱或 HAL 入队失败 */
}
```

超时单位为整数微秒。等待时间不应超过调用任务的周期；持续邮箱饱和必须作为
总线负载或物理层故障处理，不能通过无限等待掩盖。

## 诊断

`CANGetDispatchStats()` 返回接收、分发、合并和拒绝帧计数。中断路径不执行协议
解析、格式化日志或阻塞操作；任务回调同样应保持有界。
