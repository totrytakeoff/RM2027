# 安全与任务健康服务

更新日期：2026-07-23

本切片用仓库自有、与平台无关的安全状态机替代机器人应用中的局部安全布尔量，
并在开始控制调参前使 FreeRTOS 任务假设可测量、可观测。

## 安全约定

`components/services/safety` 不依赖 HAL 或 FreeRTOS。

| 状态 | 含义 | 执行器更新 |
| --- | --- | --- |
| `BOOT` | 管理器已初始化、尚未评估 | 禁止 |
| `DISARMED` | 初始化未完成、操作手关闭安全门，或严格策略下等待显式重使能 | 禁止 |
| `ACTIVE` | 所有安全输入健康 | 允许 |
| `STOPPED` | 存在至少一个运行时故障 | 禁止 |

故障原因使用位掩码，同时保留输入离线、急停、任务不健康、必需设备不健康、输入无效、
操作手解除使能和等待重使能等原因。
空输入快照按故障关闭处理。

20 ms 控制任务是安全状态转换的唯一所有者。5 ms 健康任务通过
`RobotApp_SetTaskHealth()` 发布单个原子布尔值，避免多任务同时改写执行器。
安全服务支持两种应用策略：

- 严格重使能：先在安全门关闭时观察完整安全姿态，再接收新的使能边沿；
- 电平安全门：只要硬故障清除，SA 上位即进入 `ACTIVE`，SA 下位立即进入 `DISARMED`。

正式机器人当前处于实板调试阶段，通过 `ROBOT_SAFETY_REQUIRE_EXPLICIT_REARM=0` 选择
电平安全门。这与 ET08 的操作定义一致，不再要求 SB/SC/SD 全下、四摇杆回中或新的 SA
边沿，因此不会出现 SA 已在上位却长期停在 `REARM_REQUIRED` 的情况。遥控离线、failsafe、
输入无效、初始化失败、INS 未就绪和关键任务异常仍然禁止输出。

电机反馈健康度与安全关键设备分开处理。当前
`ROBOT_SAFETY_GATE_ON_MOTOR_HEALTH=0`：单个电机掉线会输出 `ERROR` 日志，并由 5 ms
电机层只把该电机的发送槽归零，不再关闭所有在线电机；INS 仍作为安全关键设备参与
`DEVICE_UNHEALTHY`。100 ms 电机命令租约可在控制任务完全停止时拒绝过期输出。

## 任务健康约定

每个静态任务记录：

- 期望周期、运行次数和最后心跳 tick；
- 最后/最大启动间隔；
- 基于 DWT 周期计数器的最后/最大工作执行时间；
- 总超期次数和连续超期次数；
- FreeRTOS 历史最小剩余栈 words。

`ins`、`motor`、`control` 和 `health` 在以下任一条件下进入 `unhealthy_mask`：

- 100 ms 启动宽限后，超过四个配置周期无心跳；
- 连续三次释放晚于配置周期的 125%，或工作执行时间达到/超过周期；
- 历史剩余栈低于 64 words。

`diagnostics` 和 `tuning_uart` 记录同样的指标，但作为低优先级观测任务，不参与安全联锁。
当前视觉联调配置默认开启低频通用文本日志、关闭 `tuning_uart`，避免 UART6 混流；
连续调参时再切换为关闭文本日志并启用 DMA 遥测，UART 忙时丢帧。
`RobotTasks_GetHealthSnapshot()` 向遥测和调试器提供一致快照。

## 自动验证

```bash
cmake -S tests/host -B build-host -DCMAKE_BUILD_TYPE=Debug
cmake --build build-host --parallel
ctest --test-dir build-host --output-on-failure
```

主机测试覆盖启动、严格显式激活、电平门直接激活、输入丢失、急停、任务故障、
单独设备故障、多原因并存、严格模式重新布防和空参数故障关闭。
同一测试集还验证设备健康服务的毫秒截止、时钟回绕、一次性离线回调、固定容量和空参数安全。

## 仍需实板完成

- 记录六个任务连续 10 分钟的栈余量、最大执行时间和最大释放间隔。
- 分别注入每个软件故障，确认底盘、云台和发射全部停止。
- 根据实测数据而不是估计值确定最终栈和 deadline 阈值。
- 验证关键任务或整个调度器停止时 IWDG 能复位，极限正常负载不误复位。
- 实测 SA 下拨、遥控掉线和关键故障后的电机停机延迟，并确认当前电平门在故障清除且
  SA 上位时恢复、SA 下位时绝不输出。
- 分别断开一个底盘、云台和发射电机，确认只隔离掉线电机，其余在线电机仍可调试。
